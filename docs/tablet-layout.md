# タブレット表示 (2 カラムのタイムライン)

幅の広い画面では、タイムラインのカラム (Home / Notifications / Local / Global) を 2 つ横に並べて出す。

## 方針

* **閾値は 840dp** (Material 3 の Window size class の Expanded)。Google のガイドラインに 8.8 インチを名指しした基準は無く、
  参照端末の Medium Tablet (2560×1600・320dpi) は 1280×800dp。8.8 インチ級 (2560×1600) もほぼ同じなので、横向きで
  2 カラム、縦向き (約 800dp) は 1 カラムになる。
  * 幅はウィンドウの幅 (`LocalWindowInfo.containerSize`) を `LocalDensity` で dp にしたもの。画面分割にも追従し、
    `uiScale` を上げると dp が減るので 2 カラムに切り替わりにくくなる。
* **設定で上書きできる** (Display → Layout →「表示レイアウトの固定」`DisplaySettings.columnLayout`): 自動 (既定) / 1 カラム / 2 カラム。
* **ページャはそのまま**: `HorizontalPager` のページ幅を表示幅の半分にし、2 ページを同時に見せる。スワイプ・吸着・ページ位置
  (小数) の仕組みは 1 カラムと共通。`currentPage` は左端のカラム。
* **タブ**: 見えている 2 つを 1 つのまとまりとして塗る (`[[Home | Notifications] | Local | Global]`)。幅の重みは
  「区間 [pos, pos + 1] からの距離」で決め、スワイプに追従する (1 カラムは区間の幅 0 として同じ式)。
* **タブのタップ**: 見えているカラムなら一覧の先頭へ (今と同じ)。見えていなければずらす量が最小の組へ
  (例: [Home | Notifications] で Global → [Local | Global])。純粋関数 + ユニットテスト。
* **読み込み**: 見えている 2 カラムとも `ensureLoaded`。ストリーミングは元から全カラムに当てているので変えない。
* **1 ⇔ 2 カラムの切り替え** (回転・折りたたみ・設定): 選択中のカラムが見え続けるように合わせる。
* **クイック投稿バー**: 全幅に伸びないよう幅に上限を付けて中央に置く。

## 詳細のパネル

2 カラムで表示している間は、ポスト・プロフィール等をタイムラインの上に浮かぶパネル (右半分・余白付きの角丸カード) で開く。

### 経緯
* list-detail (タイムラインのペインを狭めて右に詳細を並べる) を `ListDetailSceneStrategy` (material3-adaptive-navigation3
  1.3.0) で試した (ブランチ `prototype/list-detail-a`)。並べること自体はできたが、使えなかった:
  * 2 ペインが使える幅では、Material の list-detail は詳細が無くても右に placeholder を出す。ペインの開閉が起きないので、
    Material のペインのアニメーション・予測型「戻る」の `seekTo` が出番が無い。placeholder を出すとタイムラインだけのときに
    右半分が空になり 2 カラムと両立しない。
  * タイムラインだけのときに外すと、開閉が NavDisplay の Scene の切り替えになり、白い画面が約 100ms 挟まった上で
    タイムラインごとスライドした。タイムラインも 2 → 1 カラムに飛ぶ。
  * 詳細の中の切り替え (ポスト → プロフィール) はアニメーション無しで差し替わる (中身の描画がライブラリの中で、外から
    `AnimatedContent` を挟めない)。予測型「戻る」も引いている間は何も動かない。
* 浮かぶパネルなら、タイムラインは幅もカラム数も変わらず、Scene の切り替えも起きない。メディアビューアと同じく
  `OverlayScene` に乗せ、出入り・中の切り替えはすべて自分で描く。

### 方針
* **条件**: タイムラインが 2 カラムになる条件 (`visibleColumnCount` が 2: 幅 840dp 以上、または設定で 2 カラムに固定)。
  それ以外は今までどおり全画面で積む。
* **対象の画面**: Post / Profile / Hashtag / FollowList / AccountReactions / PostReactions / OpenLink。設定・投稿画面・
  メディアビューアは今までどおり (メディアビューアはパネルの上にも重なる)。
* **Scene** (`DetailPanelSceneStrategy`): バックスタックの末尾から続く対象の画面を 1 つの `OverlayScene` にまとめ、その下
  (タイムライン等) を `overlaidEntries` として描かせる。Scene のキーは固定 (中身が替わっても NavDisplay の遷移を起こさない)。
  中では一番上の画面だけを描き、切り替えの間だけ 1 つ下も描く。
* **見た目**: 右半分に、周りに 12dp の余白を取った角丸 (28dp) のカード (影付き)。中の画面のインセットはカードの位置の分
  だけ消費する (ステータスバーの分の余白を中で取らない。キーボードの分は残す)。
* **タッチ**: カードの外は下のタイムラインに届く (読み進めながら詳細を見られる)。カードの上 (余白・角も含めたカード自体) は
  カードが受け、後ろへは通さない。
* **開き方**: タイムラインから開いても、パネルの中から開いても上に積む (「戻る」で前の画面に戻れる)。
* **アニメーション** (時間・曲線は `Transitions.kt` と同じ):
  * 開く: カードが右から入る。閉じる (最後の 1 つの「戻る」): カードが右へ抜ける。
  * 中の切り替え: 全画面のときと同じ横スライド (進む: 新しい画面が右から入り、前の画面は左へ少しずれて薄くなる)。
  * 閉じる・戻るは「アニメーションを終えてからバックスタックから外す」(外したエントリは描けないので)。戻るボタンも
    `Navigator.back()` からパネルの「戻る」を通る。
  * 予測型「戻る」: パネルの中の `NavigationBackHandler` が受け、引いた量を `PredictiveBackSettings.dampedProgress` で抑えて
    動かす。離したら残りを抜け、取り消しなら戻る。
* **戻るボタン**: パネルの最初の画面は ← ではなく ✕ (`LocalBackClosesPanel`)。
* **クイック投稿バー**: パネルを開いている間、タイムラインのバーは左側 (パネルで覆われていない所) の中央に寄せる。
  パネルの中のポスト画面は自分のバーをカードの中に出す。

### パネルについて今回は入れないもの
* **返信・下書きの挙動**: パネルのポスト画面の「自動の返信」で、タイムラインのバーまで返信になる (下書きを共有しているため)。
  後で直す。
* **画面の向き・幅が変わったとき**: パネル ⇔ 全画面の切り替えはアニメーション無しで切り替わる。
* **パネルから全画面の画面 (投稿画面・設定) を開いたとき**: パネルはアニメーション無しで消える。
* **パネルの幅の変更** (ドラッグ)・**パネルを左右どちらに出すかの設定**。
* **パネルの外のタップで閉じる**: 外はタイムラインの操作なので閉じない。

## 今回は入れないもの

* **他の画面の幅の上限**: ポスト詳細・プロフィール・ハッシュタグ・設定等は横に広がりすぎる。本文の幅に上限 (~640dp) を付けて
  中央寄せしたいが、各画面に手が入るので別に行う。
* **3 カラム以上** (1200dp 超など): 仕組み (ページ幅 = 表示幅 / N、区間の幅 N - 1) は一般化できるが、4 カラム中 3 つを
  塗るとタブの区別が付きにくい。まずは 2 に固定する。
* **カラムの並べ替え・任意の組み合わせ** (Home と Local を並べる等): 隣り合う 2 つだけ。
* **ナビゲーションレール等の大画面向けの骨組み**: 今のヘッダ (アイコン + タブ) のまま。
* **フル画面の投稿画面・メディアビューアの大画面向けの調整**: 今は全画面のまま。
* **キーボード・マウスの操作** (ショートカット・ホバー・右クリック): 未対応のまま。
